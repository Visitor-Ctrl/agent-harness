# 01 — Prerequisites and account choices

1. Prepare an OCI account, a Cloudflare account on the Free plan, a registered domain such as `example.com`, a GitHub account, and the AI subscriptions you intend to use. Domain registration is usually paid. Enable MFA and keep recovery codes offline. Use an administrator identity only for setup, separate from agent identities.
2. Choose the OCI **home region before signup**. Check latency, data residency, A1 availability, and which availability domains offer micro instances. The home region cannot later be changed. Consult [OCI regions](https://docs.oracle.com/en-us/iaas/Content/Identity/Tasks/managingregions.htm). Free compute must be available in the selected home region; a region with nearby users can still lack A1 capacity.
3. Choose **free-only** for the strongest account-level restriction against paid compute after the trial. During a trial, credits can hide paid resources. Select only resources explicitly covered by the current allowance. Choose **pay-as-you-go** only if you accept billing exposure; upgrading does not guarantee A1 capacity. Apply quotas and IAM before provisioning.
4. In OCI, open **Billing & Cost Management → Budgets → Create budget**. Target the root compartment and children, use a monthly amount of 1 unit of your billing currency (or the smallest allowed amount), and configure actual and forecast alerts with a monitored recipient. Confirm the saved rules and recipient. [Budgets](https://docs.oracle.com/en-us/iaas/Content/Billing/Concepts/budgetsoverview.htm) are soft limits, evaluated periodically, so costs can accumulate before an alert.
5. On a trusted PC install Git, OpenSSH and [cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/). On the server this guide assumes Ubuntu 24.04 LTS with systemd and cgroup v2. Run `git --version`, `ssh -V`, and `cloudflared --version` on the PC. Generate an SSH key with `ssh-keygen -t ed25519`; set a passphrase. Never upload the private key to cloud-init.
6. Keep a private setup record outside Git: home region, compartment names, resource identifiers, cost decisions, recovery method and backup recovery instructions. Use `${HARNESS_ROOT}` for the project root (for example `/srv/projects`) and profile names `profile-a` and `profile-b`. Public documentation uses only placeholders.
7. Create an owner-approved `NORTH-STAR.md` for each future project: intended users, desired outcome, scope, constraints and acceptance checks. A template is in [standards](standards/templates/new-project/NORTH-STAR.md). Without owner approval, record the missing decision; do not invent project authorization.

Exit check: sign in with MFA from a second browser, confirm recovery access, verify the selected region and billing mode, and open **Governance & Administration → Limits, Quotas and Usage**. Record actual available compute and storage. Continue only when the [budget ledger](11-free-tier-budget.md) matches your tenancy. No cloud credentials belong in this repository.
